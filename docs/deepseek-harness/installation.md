本页提供配置说明，本仓库文档修改不实际启停用户的Harness任务。只有00注册为一个定时任务；01至11不再创建独立Agent或Cron。

## 已安装多Agent时的迁移

1. 找出旧01至09的独立定时配置并停用触发；不能仅删除文档文件就认为用户任务已停止。
2. 查询实际运行状态，等待或按已有合法能力确认旧运行结束及写入权释放。不能因留言时间久杀进程、强推或抢占。
3. 保留全部原分支、PR、计划版本、评论、CI/Review和修复预算；查询真实远端动作，补齐未知结果与关联。
4. 将一个明确工作对象及其合法旧v1证据转换为00业务检查点，记录迁移来源和累计预算。旧输入缺失/分叉/权限不明时只阻塞该对象，不把计数默认0。
5. 核验00原生单运行保障后启用唯一入口。01至11均不注册，也不为CI、观察、恢复、看板或记录另建Agent；不能保留旧任务并以“降低频率”代替合并。
6. 用已有授权对象观察同一个Agent跨必要阶段的实际工作；无工作时正常结束，不人为制造测试Issue/PR。

未安装旧任务时直接配置唯一00并核验原生互斥。升级规则时协调停止受影响写入并统一版本，不改写/删除历史留言。没有永久会话能力时按GitHub检查点恢复，不假设其他Agent会提供私有记忆。

## 验证与费用

运行验收关注执行者数、重复对象/规则读取、重复Diff/日志分析、内部交接留言数量及真实结果，不只比较触发次数。记录实际usage的未缓存输入、缓存读取/写入、输出、实际费用以及完成的业务工作量。相同场景与Prompt版本才可比较；缓存命中率变化必须单独说明，不宣称固定节省比例。

规则只在首次/版本变化时完整加载，同轮已取得事实复用；实际变化和关键写入前重核。真实CI/正式Review、身份/保护和本地禁令不能为了节省token跳过。未实际安装、触发或测量的验收保持未执行。
