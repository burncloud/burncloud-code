# DeepSeek Harness 原生定时任务安装清单

本页是人工在Harness中配置任务的说明。本仓库文档PR不实际创建任务、启用事件或证明原生互斥能力存在。

每个01至09任务都使用同一份配置。以下是模板，空项需在启用对应能力前填写并核验，不能照抄占位文字当真实事实。

## 注册与最小启动条件

1. 核验GitHub连接可分页读取授权Issue/PR及留言、查询CI/Review/保护。写留言失败则对应任务只能只读，并明确通信阻塞。
2. 按[清单](scheduled-task-overview.md)注册01至09：30/15/10分钟周期各不相同。复制完整角色Prompt和上述共同配置；Prompt要求每轮按配置commit读取统一文档规则，并重读目标仓库当前AGENTS.md。10/11、agent-dispatcher及可选事件参考不注册。
3. 核验上轮未结束时不会重入；各角色同一对象写入和03代码分支必须有已验证的原生互斥保障。只看“运行中”再发认领留言不证明原子排他。能力不足时保留只读模式并阻塞相应写入。
4. 在已有授权的真实对象上观察分类→计划→开发→PR→审查/CI→门禁的留言因果链。不得为了安装演练对外部Issue留言或凭空创建测试Issue。
5. CI/正式Review缺失时保持阻塞，不本地测试、不改CI、不降低保护。合并能力仅在原有明确授权及全部门禁满足后使用，不把安装任务当作授权。
6. 08核验实际触发与留言后按10/11边界维护记录。验收字段记录message_id、comment ID/URL及实时API证据；没有执行的用例保持“未执行”。

升级协议或Prompt时先核验运行状态，协调停止受影响写入并统一规则版本；旧消息仍按其协议版本读取，无法解释的新版本不得执行。勿通过编辑历史留言迁移协议。

## 正常等待与异常

不同周期只影响接收延迟：02发计划后03下次10分钟触发读取；PR关联后04下次15分钟、05下次10分钟读取；06下次10分钟重核门禁。上轮运行、API限流和CI排队会延长等待，这些不是完成时限或进程死亡证明。

没有变化时结束本轮，不追加“无变化”留言。单轮默认最多深处理5个变化对象；本任务可使用可重建缓存优化，但下一轮须继续发现全部未处理对象，缓存丢失时从留言及实时GitHub状态恢复。

本集合不新增调度系统，不承诺空轮零模型费用，不安装Webhook。可选事件未来另行启用时仍只能加速05的同一留言处理流程。
