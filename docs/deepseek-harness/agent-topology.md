# DeepSeek Harness定时任务职责与交接

## 范围

执行者是DeepSeek Harness。基础模式为01至09共9个原生定时任务；各角色使用自己的中文Prompt。10/11是08在同一次定时执行中按需读取的记录职责，不要求子Agent、回调接口、n8n或新调度系统。

| 任务 | 负责动作 | 交接方式 |
|---|---|---|
| 01巡检 | 只读发现与白名单分类 | 保存候选项供02读取 |
| 02规划 | 有效计划、依赖与验收 | 保存计划供03读取 |
| 03开发 | 唯一写入者核验、源码和测试、提交PR | 保存分支/HEAD与检查点供04/05读取 |
| 04审查 | 需求和Diff审查 | 保存意见供03读取；证据供06读取 |
| 05CI守护 | 主动轮询CI、诊断和有限重跑 | 保存修复项供03读取；证据供06读取 |
| 06合并控制 | 重核全部门禁、绑定HEAD合并 | 保存结果供07/08读取 |
| 07看板 | 同步既有自动化字段 | 读回核验并保存结果 |
| 08观察与记录 | 实际运行观察，按10/11职责维护指定记录 | 保存文档PR和问题事项供09读取 |
| 09恢复 | 确认停止与安全恢复条件 | 保存事项供03下一轮续接 |

## 定时闭环

03每10分钟主动检查工作，无需事件启动。上轮仍运行时不重复启动；等待CI或审查时结束本轮并保存检查点。新HEAD使旧CI和审查证据失效，06必须重新查询所有门禁后才能按已有授权合并。

05每10分钟主动处理CI失败，无Webhook也能交回03。可选事件仅在未来已有明确授权和接收能力时加速同一故障记录，不是定时任务运行前提。

08读取评价档案的已有基线和运行证据，在当前任务中按10/11边界顺序维护本目录的test-cases.md与issue-log.md。不复制第二套用例，也不把文档存在写成真实运行成功。

## 权限与保护

03独占自己的源码/测试分支；04不改代码；05不改源码或CI；06独占合并且不能管理员绕过；07只写既有自动化字段；08只额外维护已有授权的两份记录文档；09不开发、不合并、不抢占未确认停止的负责者。

所有角色禁止本地编译/测试、修改CI、覆盖他人成果或关闭外部Issue。通过实际Harness运行状态和受控记录核验唯一写入者，不能依靠未实现的后台心跳、租约服务或事件邮箱。

## 交接与关闭边界

交接记录包含仓库、Issue/PR、计划版本、负责者、分支、文件范围、HEAD、实际动作、证据、状态、去重键、累计修复次数与下一动作。只能报告已保存和已验证的事实。

本集合不自动关闭Issue。08按10职责提供全量验收材料，已有明确授权的关闭流程仍须重新核验原始创建者、子任务和全部验收条件。父Issue部分交付保持开放。
