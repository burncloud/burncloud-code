# DeepSeek Harness Agent 角色与交接

## 控制平面与角色

Scheduler提供定时触发、事件接收和队列；持久化状态存储提供去重、任务租约、执行槽与会话检查点。总调度调用[任务派发协议](agent-dispatcher.md)，管理开发worker、worktree与分支。控制能力无需另建一个定时模型Agent；实际能力必须核验后才能声称可用。

本集合注册8个定时入口和2个事件入口。11份原Prompt文件保留职责隔离；10/11是按需记录职责，03是事件worker。另有一个CI失败事件Prompt及一份派发控制协议，文件数量不等于定时任务数量。

| 编号/入口 | 角色 | 唯一负责动作 | 交接对象 |
|---|---|---|---|
| 01定时 | Issue自动巡检 | 只读发现、白名单核验和分类 | 02 |
| 02定时 | 任务规划 | 增量实施计划、依赖和验收条件 | 派发控制 |
| 派发控制 | 调度器能力 | 原子认领、执行槽、worker、分支与文件归属 | 03 |
| 03事件 | 代码开发 | 独占分支源码与测试、提交PR、修复 | 04、05 |
| 04定时 | PR审查 | 需求和Diff审查、审查意见 | 派发器→03修复；06审查证据 |
| 05定时 | CI守护 | 当前HEAD对账、有限远端重跑 | CI失败入口；04、06证据 |
| CI失败事件 | 故障接收与路由 | 验签、去重、API核验、故障归一化 | 派发器→03；05重跑；11记录 |
| 06定时 | PR合并控制 | 最终门禁、绑定HEAD合并 | 07、10 |
| 07定时 | Projects管理 | 既有自动化字段同步 | 持久化结果 |
| 08定时 | Harness运行观察 | 健康、异常、安全边界和成本报告 | 09；10/11记录回调 |
| 09定时 | 故障恢复 | 核验原负责者后安全恢复租约 | 派发器与11 |
| 10回调 | 验收记录 | 维护指定验收文档及真实证据 | 07；已有授权的关闭流程 |
| 11回调 | 问题日志 | 去重维护指定问题文档 | 对应负责角色 |

## 正常开发与修复

01发现候选项；02生成计划；派发器再次核验身份、依赖、归属与预算，原子取得任务租约及执行槽，再启动03。03持续推进当前任务，提交后04/05可独立读取同一HEAD。等待CI/Review释放执行槽，保留会话与分支，不以Cron每轮重启。

04发现源码问题时通过派发器送回原03会话。Webhook失败事件与05轮询发现的失败共用同一业务去重键和修复租约；事件入口不写源码或重跑，源码失败归03、基础设施有限重跑归05、CI配置问题只记录阻塞。

新HEAD使旧CI与审查证据失效。06仅在全部门禁满足并再次读取真实GitHub状态后，按预期HEAD受保护合并；结果经GitHub和目标分支核实后交给07/10。合并或回调不是全量验收完成。

## 观察、恢复与记录

08读取调度和租约事实，也读取 `docs/deepseek-harness-evaluation/` 既有基线与档案；没有新事实只保存巡检检查点。需要记录时将证据交给10/11，它们仍独占各自文档写入权，按变化批量提交文档PR，不增加独立定时入口。

09只核验并恢复调度、租约与交接，不能写源码、重跑CI或合并。疑似停止需确认旧worker不能继续写入，再通过派发器恢复原会话或安全重新分配。

当前维护目标仍为文档仓库本目录的 `test-cases.md` 和 `issue-log.md`；评价档案只读引用，未经额外明确授权不扩大写入范围或复制第二套测试记录。

## 权限与状态分离

- 02只规划，派发器才认领。worker数、工作树、分支和文件归属集中管理。
- 同一对象只有一个有效写入者；同一PR当前HEAD的多条故障汇入原会话邮箱。
- 03只写自己归属的源码/测试；04独立审查，不批准自己的PR；05只诊断和有限重跑。
- 06是唯一合并角色，仅在已有用户授权内操作，不管理员绕过或启用延迟自动合并。
- 07只改既有自动化管理字段；08只观察；09只安全恢复；10/11只写指定文档。
- 所有角色禁止本地编译/测试、修改CI、覆盖他人成果或关闭外部Issue。

## 交接数据与预算

交接包含仓库、Issue/PR、计划版本、文件范围、负责者、会话ID、租约版本、分支、当前HEAD、事件/故障批次、实际动作、证据、状态、阻塞原因、下一动作及预算余量。

默认2个开发槽，单轮巡检最多深处理5个变化对象；余项排队。无变化不调用模型，普通状态和身份判断用程序处理，复杂计划/审查/诊断才按需使用模型。无法核验持久化、原子锁和过期worker写入隔离时暂停相应写操作。

## Issue关闭边界

本集合不自动执行关闭。10输出全量验收证据；已有明确授权的关闭流程仍须重核原始创建者、全部子任务、验收和真实GitHub状态。大型父Issue部分交付不能触发关闭关键字。
