# BurnCloud DeepSeek Harness 自主研发任务集合

本目录提供可直接复制给 DeepSeek Harness 的中文定时任务 Prompt。文件名保留英文与两位数字顺序，正文、任务名称、状态说明和调度格式使用中文；GitHub、API 字段、命令、路径等技术标识保留原样。

## 架构判断与入口数量

采用 **8个定时入口 + 2个事件入口**。角色数量、Prompt 文件数量和独立注册的任务数量分别计算，不能把每个记录职责都建成一个定时 Agent。

原11项方案实际包含9个定时任务、1个持续开发任务和1个CI失败事件；统一每30分钟会增加等待延迟，并反复唤醒开发和记录角色。本版将派发移入调度器控制能力，开发改为事件启动的持续 worker，记录角色按需调用，保留所有权限和职责隔离。

| 类型 | 入口或职责 | 数量 | 运行方式 |
|---|---|---|---|
| 定时入口 | 01、02、04、05、06、07、08、09 | 8 | 各自按周期增量对账，有工作才深入处理 |
| 事件入口 | 03代码开发、CI失败处理 | 2 | 派发事件与Webhook/轮询补偿事件 |
| 控制能力 | 任务派发 | 不计独立任务 | 管理租约、执行槽、会话、工作树与分支 |
| 记录职责 | 10验收记录、11问题日志 | 不计独立任务 | 新证据或异常产生后按需回调 |

旧文件名与路径保留，不代表目录中的每个文件都应注册Cron。必须按[入口清单](scheduled-task-overview.md)显式注册，不能按文件目录自动扫描安装定时器。

## 使用方式

1. 阅读目标仓库 `AGENTS.md` 与[本地执行及 CI 冻结策略](../bam-local-execution-policy.md)。
2. 阅读[角色与交接](agent-topology.md)、[调度总览](scheduled-task-overview.md)与[任务派发协议](agent-dispatcher.md)。
3. 仅为01、02、04、05、06、07、08、09复制完整Prompt并注册定时入口，按各文件末尾的“执行配置”设置中文名称、周期和无人值守模式。
4. 把03注册为派发事件驱动的worker，持续推进当前可执行工作；等待CI或Review时保存检查点并释放执行槽。
5. 把[CI失败处理](event-tasks/ci-failure-handler.md)注册为外部事件入口；缺Webhook能力时由05补偿，明确标记即时入口未启用。
6. 将10/11作为总调度按需调用的记录职责，不另设定时器或事件消费者。
7. 配置已有授权的GitHub连接、持久化记录、原子租约及各角色最小权限；派发默认最多2个活跃开发worker。
8. 观察真实调度、GitHub和CI记录后，将结果写入[验收记录](test-cases.md)与[问题日志](issue-log.md)。

本次交付是Prompt和协议文档。文档存在不代表Harness已安装任务、已实现权限隔离或已通过运行验收。必要能力无法核验时只读并记录阻塞。不新增CI Workflow、不部署n8n、不创建Webhook或修改仓库权限。

## 模型调用与上下文预算

巡检、身份、去重、状态对账、看板同步和合并条件使用普通程序或已具备能力的执行器处理；没有程序实现时可以由Harness执行相同受控动作，但不能宣称已节省模型开销。

规划、源码开发、实质代码审查和必要的复杂诊断才调用模型。周期触发不等于每轮模型调用：无变化、无授权工作或同一证据已处理时结束本轮。

每次worker只加载自己的Prompt、当前计划、相关文件和精简日志。共享状态保存到持久化记录，以链接取用GitHub证据；不向每个Agent复制整套历史或11份Prompt。默认单轮巡检最多深处理5个变化对象，剩余排队并保存分页检查点；不能因批次限制丢弃未扫描对象。

安全核验由各角色既有门禁完成；运行报告由08输出、事实记录由10/11维护，不另增安全或报告定时Agent。n8n仅是可选控制平面，状态DB、队列和权限边界仍是必须核验的能力。

## 强制边界

禁止本地编译、类型检查、测试和 Clippy，包括间接脚本、Git hook、容器及其他语言测试运行器。源码与测试可以在本地编写，所有构建、测试和质量验证由 GitHub Actions 执行。

禁止修改、新建、删除、移动、重命名 Workflow、CI 门禁配置、触发条件、测试命令、路径过滤及分支保护。现有 CI 不覆盖必要测试时记录阻塞，不自行新增或放宽 CI。

PR 审查不修改代码、不合并；CI 守护只诊断与有限重跑；代码开发负责源码和测试修复；合并控制独占合并权限。其余角色只处理自己的元数据或指定文档。

同一对象只有一个有效写入者。调度器必须提供持久化去重、原子锁与租约；Prompt 本身不能保证并发隔离。没有这些能力时相应写操作阻塞，不以普通评论当作原子锁。

## 中文状态与机器标识

用户可见结果使用中文。与既有状态机、看板或接口交互时使用既有机器标识，不改写 API 枚举，也不另建状态机。巡检分类和审查结论是角色输出，不是需求追踪状态。

| 中文说明 | 既有机器标识 | 使用范围 |
|---|---|---|
| 未开始 | `NOT_STARTED` | 需求进度 |
| 开发进行中 | `IN_PROGRESS` | 需求进度 |
| 本地静态差异已检查 | `LOCAL_VERIFIED` | 仅既有状态要求时使用；不表示本地编译或测试 |
| 等待 CI | `WAIT_CI` | 需求进度 |
| CI 失败 | `CI_FAILED` | 需求进度 |
| 满足合并门禁 | `READY_TO_MERGE` | 需求进度；须全部证据完整 |
| 已合并 | `MERGED` | 已核实目标分支含代码 |
| 验收完成 | `VERIFIED` | 最终验收真实通过 |
| 任务阻塞 | `BLOCKED` | 依赖、授权或证据缺失 |
| CI 覆盖阻塞 | `BLOCKED_CI_COVERAGE` | 阻塞原因，非新增进度状态 |
| CI 不可用阻塞 | `BLOCKED_CI_UNAVAILABLE` | 阻塞原因，非新增进度状态 |
| 等待人工审批 | `Awaiting Human Approval` | 合并控制结论，非新增需求状态 |

## 执行记录与完成条件

记录仓库、对象链接、Agent、时间、HEAD SHA、真实动作、证据、状态、阻塞原因、下一负责者、去重键和持久化位置。CI 证据必须包含当前 HEAD 的 run/job/check ID、URL、运行尝试与实际执行范围。

创建 PR、绿色徽章、未执行用例、旧 HEAD 成功及等待都不能当作完成。合并后核实目标分支；父 Issue 必须全部验收才可进入已有授权的关闭流程。本集合没有自动关闭 Issue 的角色。

详细行为对照保留在[现有测试档案](../deepseek-harness-evaluation/README.md)，本目录引用这些档案，不另建重复测试目录。
