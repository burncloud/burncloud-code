# DeepSeek Harness 单Agent工作选择与安全续接

本文件只定义00内部选择工作，不是Dispatcher Agent、独立定时任务、外部队列或子Agent派发接口。

## 选择与复用

1. 查真实前轮运行状态和原生互斥，前轮仍活跃则退出。不能先发认领留言再声称独占。
2. 优先原有可执行活动PR、当前有效修复和未完成计划，再挑新授权Issue；仅等待无变化的对象不阻塞其他独立候选。默认深处理一个增量，轻量候选最多5个，未处理项下轮仍可发现。
3. 为选定对象建立一份需求、计划、分支/HEAD、CI、Review、预算和下一动作快照；按需进入阶段，不为每个阶段扫描所有对象或重建同一上下文。
4. 同轮直接继续可执行步骤，等待外部CI/Review/依赖时保存必要检查点并结束，不为了阶段切换等待下一轮。
5. 缓存丢失时分页恢复原Issue与关联PR留言和真实API事实；不能重复创建分支/PR或清空预算。

## 独占与失效

业务分支只允许一个有效写入者。实际原生互斥能力不足时阻塞相关写入，不新增锁服务或用普通留言充当锁。多个独立开发者仍有冲突时让出受影响范围，不覆盖他人成果。

需求依据变动时重评计划，HEAD/比较基线变化时更新Diff分析，最新CI attempt/Review/保护变化时刷新对应证据。外部写入前重核关键事实，合并前完整重新查询门禁并绑定预期HEAD；“本轮已读”不等于永久有效。

同根因源码修复3轮、临时重跑1次、恢复1次，沿原检查点链跨HEAD累计。未知动作先查询真实commit/PR/run/merged状态再补记，不能盲目重复。实际停止核验与安全移交成立才可恢复；时间久、留言超时或缺未配置心跳不证明停止。

## 记录

阶段结果先留在本轮上下文；跨轮的计划/关联/实际动作/终态/阻塞/验收变化按[检查点协议](communication-protocol.md)聚合保存。不为每个阶段发收到或完成回执。不把记录文件当工作队列。
